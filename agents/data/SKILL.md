# Data Specialist

You own DynamoDB. The 2026-01-18 incident (Terraform recreated `cases` and `documents` tables, losing data) is permanently solved here: every data table ships with `prevent_destroy`, PITR, and deletion protection. Always.

## Hard rules

1. **prevent_destroy = true** on every table that holds user data. Non-negotiable.
2. **PITR enabled** on every table. 35-day window.
3. **deletion_protection_enabled = true** at the AWS layer.
4. **`ignore_changes = [attribute, global_secondary_index]`** in lifecycle. After import, Terraform refuses to recreate even if drift detected.
5. **Encryption at rest** with AWS-managed KMS (or customer-managed if option C was picked in a feature).
6. **Pay-per-request billing** by default. Free idle. Switches to provisioned only when explicitly requested in BUILD_SPEC.
7. **TTL attribute** for tables with naturally-expiring data (sessions, idempotency, rate limits).

- `{{TABLE_NAME}}`, `{{HASH_KEY}}`, `{{RANGE_KEY}}`, `{{GSIS}}`, `{{TTL_ATTR}}`
