# /jarvis-adopt — adopt an existing AWS account

The user has prior AWS work (manual console clicks or other IaC). Jarvis imports it into Terraform with safety rails, so they can continue using AWS with Jarvis without losing existing state.

## Preamble

```bash
AWS_ID=$(aws sts get-caller-identity --output json 2>/dev/null) || { echo "BLOCKED: no AWS creds"; exit 1; }
echo "ACCOUNT: $(echo "$AWS_ID" | jq -r .Account)"
echo "REGION: ${AWS_REGION:-${AWS_DEFAULT_REGION:-us-east-1}}"
```

## Step 1: Discovery scan

For each resource type, list what's in the account:

```bash
# DynamoDB
aws dynamodb list-tables --output json | jq -r '.TableNames[]'

# S3
aws s3api list-buckets --output json | jq -r '.Buckets[].Name'

# ECS clusters
aws ecs list-clusters --output json | jq -r '.clusterArns[]'

# Lambda functions
aws lambda list-functions --output json | jq -r '.Functions[].FunctionName'

# Secrets Manager
aws secretsmanager list-secrets --output json | jq -r '.SecretList[].Name'

# RDS instances
aws rds describe-db-instances --output json | jq -r '.DBInstances[].DBInstanceIdentifier'
```

Compile a discovery report and surface it:

> Found 47 AWS resources in account 618143339406 us-east-1:
>   - 14 DynamoDB tables
>   - 8 S3 buckets
>   - 2 ECS clusters (4 services)
>   - 11 Lambda functions
>   - 6 Secrets Manager secrets
>   - 1 RDS instance
>   - ... (full list in .jarvis/discovery.json)
>
> Adopt all into Terraform with safety rails?
>   A) Yes, generate import blocks for everything (recommended)
>   B) Pick which to adopt (interactive)
>   C) Cancel

## Step 2: Generate Terraform + import blocks

For each resource discovered, write a Terraform file with:
1. The resource block (matching live state)
2. An import block (Terraform 1.5+) pointing at the existing resource
3. `prevent_destroy` + `ignore_changes` lifecycle if it holds data

Example for a DynamoDB table:

```hcl
# Generated by Jarvis /jarvis-adopt on 2026-06-08
# Imported from existing account 618143339406
# DO NOT REMOVE the lifecycle block — protects existing data

import {
  to = aws_dynamodb_table.users
  id = "users"
}

resource "aws_dynamodb_table" "users" {
  name         = "users"
  hash_key     = "id"
  billing_mode = "PAY_PER_REQUEST"

  attribute {
    name = "id"
    type = "S"
  }

  point_in_time_recovery {
    enabled = true   # Jarvis adds this if not present
  }

  lifecycle {
    prevent_destroy = true
    ignore_changes  = [attribute, global_secondary_index]
  }
}
```

## Step 3: Run terraform init + plan

```bash
cd iac && terraform init && terraform plan -out=adopt-plan
```

If the plan shows ANY destroys, halt — something doesn't match. The user must investigate before applying.

## Step 4: Apply

```bash
terraform apply adopt-plan
```

Terraform now manages the existing resources. Future `/jarvis-add-X` commands will see them and integrate.

## Step 5: Profile sync

Generate `.jarvis/profile.json` reflecting the adopted state:
